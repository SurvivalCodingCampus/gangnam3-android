### 1. 안드로이드 UI State 홀더 패턴
  화면에 보여줄 데이터(검색어, 레시피 목록, 로딩 중인지 여부 등)가 많아질수록 매니저(ViewModel) 머릿속이 복잡해지고 실수할 위험이 커져요.
  UI State 홀더 패턴은 이렇게 흩어진 상태들을 하나의 깔끔한 상자(data class나 sealed interface)에 묶어서 관리하는 정리 비법입니다.

1) 화면 상태 vs 위젯 자체 상태화면 상태 (Screen UI State): 
  -  레시피 목록, 검색어, 로딩 상태처럼 화면 전체 데이터와 관련된 상태로, 매니저(ViewModel)가 관리해요.   
  -  위젯 자체 상태 (UI Element State): 버튼이 눌렸는지, 체크박스가 켜졌는지처럼 작은 부품(위젯) 스스로 잠깐 기억하는 상태로, remember()로 관리해요.   
2) 하나씩 흩어놓지 말고 한 상자에 담기 (data class + copy())
  -  검색어, 목록, 로딩 여부를 따로따로 변수로 두면 헷갈리기 쉬워요.   
  -  이를 SearchRecipesState 같은 하나의 상자(data class)에 넣어 두고, 값을 바꿀 때는 기존 상자를 마구 고치는 대신 copy()로 복사해서 바뀐 부분만
     살짝 고친 새 상자를 건네줘요.   
3) data class vs sealed interface (언제 뭘 쓸까?)단일 data class: 
  -  검색 화면이나 로그인/회원가입 폼처럼 로딩 중에도 기존 입력값이나 목록이 같이 유지되어야 할 때 잘 어울려요.   
  -  sealed interface: 목록 조회나 상세 화면처럼 로딩 중 / 성공 / 실패 상태가 서로 겹치지 않고 딱딱 나뉠 때 쓰면, when 분기에서 빼먹는 실수를 
     컴파일러가 미리 막아줘요.   
4) 화면이 보일 때만 살뜰하게 듣기 (collectAsStateWithLifecycle())
  -  앱이 백그라운드로 내려갔을 때까지 굳이 화면 상태를 계속 수집할 필요는 없어요.   
  - collectAsStateWithLifecycle()을 쓰면 화면이 실제로 보일 때(STARTED)만 데이터를 받아오고, 안 보일 때는 멈춰서 자원을 아껴준답니다.

### 2. 오늘의 핵심 명령어 모음.
    data class ...State(...)       여러 화면 상태를 한 객체로 묶는 상태 홀더      검색어·목록·로딩 상태를 한데 담은 만능 알림장 상자   
    .copy(...)                     불변 객체의 일부 값만 바꿔 새 객체 생성        기존 알림장을 훼손하지 않고 필요한 칸만 고쳐서 복사본 만들기   
    _state.update { ... }          스레드 안전하게 StateFlow 상태 갱신          여럿이 동시에 고쳐도 꼬이지 않게 안전하게 새 복사본으로 갈아끼우기   
    sealed interface               상호 배타적인 화면 상태(Loading, Success, Error) 정의     "로딩 중이냐, 성공이냐, 에러냐" 중 하나만 고르게 하는 전용 칸막이 상자
    collectAsStateWithLifecycle()  생명주기를 인식해 StateFlow를 Compose State로 변환        화면이 켜져 있을 때만 귀를 기울이고 꺼지면 쉬는 똑똑한 수신기
