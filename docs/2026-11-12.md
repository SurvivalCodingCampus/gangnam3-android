# 상태 없는 Composable 작성 규칙

## 용어 및 개념 정리
- Stateless Composable (상태 없는 컴포저블): 내부에 상태를 두지 않고, 표시할 값과 이벤트 콜백을 파라미터로 받는 컴포저블
- Stateful Composable (상태 있는 컴포저블): `remember { mutableStateOf(...) }`로 상태를 직접 만들고 관리하는 컴포저블
- State hoisting (상태 끌어올리기): 상태를 호출하는 쪽으로 옮겨서, 컴포넌트는 `value`를 받고 `onXxx: (T) -> Unit` 콜백으로 변경을 알리는 패턴
- 단방향 데이터 흐름 (UDF): 상태는 위(호출부)에서 아래(컴포넌트)로 내려가고, 이벤트는 아래에서 위로 올라감

## 핵심 코드
```kotlin
@Composable
fun Tabs(
    labels: List<String>,
    selectedIndex: Int,
    onValueChange: (Int) -> Unit,
    modifier: Modifier = Modifier,
) {
    Row(modifier = modifier) {
        labels.forEachIndexed { index, label ->
            val isTapped = selectedIndex == index
            Box(
                modifier = Modifier
                    .weight(1f)
                    .clickable { onValueChange(index) },
            ) {
                Text(text = label)
            }
        }
    }
}

setContent {
    var selectedIndex by remember { mutableIntStateOf(0) }
    Tabs(
        labels = listOf("Label", "Label"),
        selectedIndex = selectedIndex,
        onValueChange = { selectedIndex = it },
    )
}

@Preview(showBackground = true)
@Composable
private fun TabsPreview() {
    Tabs(labels = listOf("Label", "Label"), selectedIndex = 0, onValueChange = {})
}
```

## 오류 해결 및 인사이트
- 인사이트: 상태 없는 컴포넌트는 콜백을 받기만 하고 실제 값은 바꾸지 않는다
  - `InputField`에 `onValueChange = {}`를 넘기면 타이핑해도 글자가 입력되지 않는다
  - 호출부에서 `onValueChange = { text = it }`처럼 상태를 갱신해야 화면이 다시 그려진다
- 인사이트: 컴포넌트 내부에서 크기를 고정하면 재사용성이 떨어진다
  - `InputField`, `Tabs`가 내부에서 `modifier.fillMaxSize()`를 적용해 화면 전체를 차지함
  - 크기와 배치는 호출하는 쪽이 `modifier`로 정하도록 내부의 `fillMaxSize()`를 빼는 것이 좋다
- 인사이트: Modifier는 적용 순서가 결과에 영향을 준다
  - `Tabs`에서 `.padding()` 다음에 `.clickable()`을 두면 클릭 영역이 padding 안쪽으로 줄어든다
  - 탭 전체를 클릭 영역으로 쓰려면 `.clickable()`을 `.padding()`보다 앞에 둔다
- 인사이트: `Int` 상태에는 `mutableIntStateOf`를 사용한다
  - `mutableStateOf(0)`과 달리 박싱(boxing)이 일어나지 않는다
