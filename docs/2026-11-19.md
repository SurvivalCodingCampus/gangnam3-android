### 1.  안드로이드 MVVM패턴.
    -  햄버거 가게에 비유한 "MVVM 패턴"이란?
       앱을 만들 때 모든 코드를 한 곳에 뭉쳐 놓으면 나중에 고칠 때 엄청 헷갈려요. 
       그래서 역할을 View(손님용 카운터), ViewModel(매니저님), Repository & DataSource(주방과 식재료 창고)로 깔끔하게 나누는 
       정리 정돈 규칙이 바로 MVVM 패턴입니다!
    1. 초등학생 눈높이로 이해하는 MVVM 역할 놀이
      1) View (예쁜 카운터 & 메뉴판)
        - 우리가 스마트폰 화면에서 직접 보고 터치하는 곳이에요.   
        - 카운터 직원은 복잡한 요리법이나 창고 재고를 몰라도 돼요. 그냥 "매니저님이 주신 메뉴판을 예쁘게 보여주고, 손님이 버튼을 누르면 
          매니저님께 알려드리는 역할"만 해요.   
      2) ViewModel (똑똑한 매장 매니저님)
        - 화면(View)과 창고(Repository) 사이에서 일하는 두뇌이자 중재자예요.   
        - 손님이 "치즈버거 검색해 주세요!" 하면 창고에서 재료를 가져오게 시키고, 화면이 보여주기 딱 좋게 정리해서 전달해 줘요.   
        스마트폰 화면을 빙글 돌려도 매니저님은 자리를 지키고 있어서, 화면이 바뀌어도 데이터가 사라지지 않게 지켜준답니다!   
      3) Repository & DataSource (식재료 창고 & 창고지기)
        - 인터넷 서버, 데이터베이스, 파일 등에서 진짜 데이터(레시피 목록, 사진 등)를 가져오는 곳이에요.   
        - 내일 카운터 인테리어나 메뉴판 디자인이 싹 바뀌어도, 식재료 창고(Repository)는 건드릴 필요가 없도록 독립적으로 만들어 둡니다.   
      4) LazyColumn (똑똑한 진열대) & Coil (사진 배달부)
        - LazyColumn: 긴 목록을 보여줄 때, 화면에 지금 보이는 몇 개만 쏙쏙 그려서 스마트폰 배터리를 아껴주는 똑똑한 세로 진열대예요.   
        - Coil: 인터넷 주소(URL)에 있는 음식 사진을 빠르고 가볍게 불러와 화면에 띄워주는 사진 배달부예요

### 2. 오늘의 핵심 명령어 모음.
    ViewModel()                    화면용 데이터를 보관하고 관리하는 클래스          화면을 지켜주는 듬직한 매니저님   
    MutableStateFlow / StateFlow   상태 변화를 자동으로 알려주는 데이터 통           값이 바뀌면 화면에 "새로 그려줘!" 하고 소문 내는 통   
    viewModelScope.launchViewModel 안에서 백그라운드 작업 실행                     매니저님이 바쁜 일을 시킬 때 쓰는 전용 작업실 (화면 닫히면 자동 정리)   
    collectAsState() /             Flow데이터를 Compose 화면 상태로 변환           매니저님이 주는 실시간 데이터를 화면이 알아듣게 바꾸는 통역기
    collectAsStateWithLifecycle()    
    LazyColumn + items(key = ...)  화면에 보이는 항목만 효율적으로 스크롤 목록 표시   보이는 것만 그리는 똑똑한 세로 스크롤 목록   
    AsyncImage(...)                인터넷 이미지 URL을 비동기로 불러와 표시          인터넷에서 사진을 가져와 보여주는 이미지 상자   
    by lazy                        실제로 필요할 때 처음 한 번만 객체 생성           쓸 일이 생길 때까지 아껴뒀다가 처음 쓸 때만 만드는 마법   
    MainDispatcherRule + runTest   화면(Main) 스레드 없이도 ViewModel 단위         진짜 폰을 켜지 않고도 컴퓨터 안에서 매니저님 
                                   테스트 실행                                    일 처리를 미리 시험해 보는 도구

#### 회고.
유지보수와 확장성의 체감:
화면 코드 안에 데이터 조회와 상태 변경 로직이 섞여 있을 때보다, ViewModel과 Repository로 책임을 나누니 각 계층의 역할이 훨씬 선명해지고 
수정이나 기능 확장이 수월하다는 점을 확실히 느꼈습니다.

붙일 때도 훨씬 안정적으로 개발할 수 있을 것 같습니다.
