### 1. 안드로이드 "고급상태관리기법"
1) Screen (순수하게 그림만 그리는 화가)화가는 물감과 붓(state와 onClick 같은 콜백)만 받아서 화면을 예쁘게 그리는 일만 해요.
   화가에게 "직접 창고 가서 재료 가져와!", "다른 방으로 이동해!" 같은 심부름을 시키지 않아요. 덕분에 언제든 가짜 물감(Preview 더미 데이터)을 주고 
   그림이 잘 그려졌는지 쉽게 확인할 수 있답니다.
2) Root (뒤에서 연결해 주는 무대 감독님)SearchRecipesRoot 같은 Root 컴포넌트가 무대 뒤에서 ViewModel을 데려오고, 상태가 바뀔 때마다 
   화가(Screen)에게 새 상태를 건네줘요.화면 이동(Navigation), 다이얼로그나 스낵바 띄우기, 권한 요청 같은 외부 연결 일도 모두 감독님(Root)이 맡아요.
3) Preview에서 자유자재로 시험해 보기Screen이 ViewModel에 묶여 있지 않기 때문에, 프리뷰(@Preview)에서 검색어가 "chicken"일 때, 목록이 비어 
   있을 때 등 원하는 상황을 마음대로 만들어서 미리 구경할 수 있어요.

### 2. 오늘의 핵심 명령어 모음.
...Screen(state, onEvent)          상태와 콜백만 받아 UI를 그리는 순수 UI 컴포저블                   물감과 명령만 받아 예쁘게 그림 그리는 화가   
...Root(viewModel = viewModel())   ViewModel 주입, 상태 구독, 화면 이동·이벤트 등 외부 의존성 처리    뒤에서 ViewModel과 화면 이동을 챙기는 무대 감독님   
viewModel::onQueryChanged          ViewModel의 이벤트 처리 함수를 콜백으로 넘기는 함수 참조           감독님이 화가에게 건네는 "이 버튼 눌리면 이 일 해줘!" 직통 연락처   
collectAsState() /                 ViewModel의 StateFlow를 관찰해 Screen에 전달할 State로 변환
collectAsStateWithLifecycle()                                                                  감독님이 ViewModel의 최신 소식을 받아 화면에 전해주는 통역기   
@Preview                           외부 의존성 없이 더미 상태로 화면 UI를 미리 렌더링해 검증           실제 무대에 오르기 전에 리허설로 그림을 미리 확인해 보는 거울

#### 회고.
-  책임이 나뉘니 코드가 훨씬 맑아진 경험: 
   화면 코드에 ViewModel이나 바텀시트 같은 외부 요소가 섞여 있을 때보다, Root로 책임을 걷어내니 각 파일이 무엇을 해야 하는지 훨씬 명확해졌습니다.

   커져도 흔들리지 않는 구조를 체감할 수 있었습니다.
