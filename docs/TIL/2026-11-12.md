## Compose

> **Compose**는 영어로 '구성하다', '조립하다'라는 뜻 작은 UI 조각(Composable 함수)들을 레고 블록처럼 조합해서 화면을 만든다는 의미를 담고 있음

### Compose 함수

> `@Composable` 어노테이션이 붙은 함수로, Jetpack Compose에서 UI를 구성하고 조립하는 최소 단위.

- **컴포저블**:  UI로 구성가능한 함수
- **네이밍 컨벤션:** 일반 함수와 구분하기 위해 첫 글자를 대문자로 시작하는 파스칼 케이스
- **조합성:** 다른 컴포저블 함수를 호출하여 레고 블록처럼 UI를 계층적으로 조립 가능.
- **리컴포지션(Recomposition):** 내부에서 참조하는 상태(State)가 변경되면, Compose 런타임이 해당 함수를 다시 호출(재실행)하여 UI를 자동으로 갱신.
- **빠른 실행과 반복:** 상태 변화에 따라 매우 자주, 순식간에 재실행될 수 있으므로 내부에 무거운 로직이나 부수 효과(Side-effect)를 넣지 않아야 함.

### @Preview

> 앱을 실제로 빌드하거나 에뮬레이터/기기에 실행하지 않고, Android Studio의 디자인 창에서 컴포저블(Composable) UI를 미리 볼 수 있게 해주는 어노테이션.

- 반드시 `@Composable` 어노테이션과 함께 사용해야 함.
- 프리뷰 전용 함수는 **매개변수를 받지 않아야 함** (만약 파라미터가 있다면 기본값을 지정하거나 `@PreviewParameter`를 사용해야 함).
- 반환값이 없는(`Unit`) 함수여야 함.
- 주요 속성 (옵션):
    - `showBackground = true`: 투명 배경 대신 기본 흰색 배경을 깔아 UI 경계를 명확하게 표시.
    - `showSystemUi = true`: 상단 상태바와 하단 내비게이션 바를 포함한 전체 기기 화면 형태로 표시.
    - `name = "..."`: 프리뷰 창에 표시될 이름 지정 (여러 프리뷰를 구분할 때 유용).
    - `uiMode = Configuration.UI_MODE_NIGHT_YES`: 다크 모드 상태의 UI 미리보기.
    - `widthDp`, `heightDp`: 특정 화면 크기를 지정해 미리보기.
### XML -> Compose 전환 이유

- **상태 동기화 자동화:** 데이터가 바뀌면 개발자가 직접 뷰를 찾아 수정(Getter, Setter 노출)할 필요 없이 UI가 알아서 갱신됨 (동기화 버그 감소).
- **코드 간결성 및 응집도:** XML과 Kotlin 코드로 분리된 구조를 Kotlin 단일 언어로 통합해 보일러플레이트 코드 감소.
- **쉬운 재사용성:** 무거운 커스텀 뷰 대신 `@Composable` 함수 단위로 가볍게 UI를 조립하고 재사용 가능.
- **렌더링 성능 최적화:** 깊은 뷰 계층 구조를 줄이고, 상태가 변한 부분만 다시 그리는 스마트 리컴포지션(Recomposition) 지원.
- **멀티플랫폼 확장성:** Kotlin 문법을 온전히 활용하며 Kotlin Multiplatform(KMP)을 통한 타 플랫폼 UI 공유 가능.

### 속성들

- **Column (수직 배치)**
    - 자식 요소를 위에서 아래로 **세로 방향**으로 순서대로 나열.
    - 주요 속성: `verticalArrangement` (수직 방향 정렬 및 아이템 간격), `horizontalAlignment` (가로 축 기준 정렬).

- **Row (수평 배치)**
    - 자식 요소를 왼쪽에서 오른쪽으로 **가로 방향**으로 순서대로 나열.
    - 주요 속성: `horizontalArrangement` (가로 방향 정렬 및 아이템 간격), `verticalAlignment` (세로 축 기준 정렬).

- **Box (겹치기 배치)**
    - 자식 요소를 동일한 공간에 **겹쳐서 배치** (나중에 작성된 코드가 위쪽 레이어에 얹어짐).
    - 주요 속성: `contentAlignment` (전체 자식 기본 정렬), 각 자식별 위치 변경은 `Modifier.align()` 사용.

- Modifier
    - 컴포저블의 크기, 모양, 디자인, 동작(클릭 등)을 변경하고 꾸며주는 데코레이터 객체.
    - **적용 순서의 중요성:** 모디파이어의 **작성 순서가 결과에 직접적인 영향**을 미침 (예: `background`를 먼저 지정하고 `padding`을 주는 것과, `padding`을 주고 `background`를 주는 것은 화면에 그려지는 결과가 다름).
    - 주요 속성:
        - **크기 및 여백:** `size`, `width`, `height`, `padding`, `fillMaxWidth`
        - **시각적 스타일:** `background`, `border`, `clip`, `shadow`
        - **사용자 인터랙션:** `clickable`, `draggable`
        - **레이아웃 제어:** `weight`(Row/Column 안에서 공간 비율 배분), `offset`(위치 미세 조정)

- dp (Density-independent Pixel)
    - 정의: 화면의 픽셀 밀도(DPI)와 상관없이 **물리적으로 동일한 크기**를 유지하는 단위.
    - 용도: 컴포넌트의 크기, 마진, 패딩, 높이/너비 등 **일반 UI 요소**에 사용.

- sp (Scale-independent Pixel)
    - 정의: `dp`와 동일하게 작동하지만, 사용자의 시스템 글꼴 크기 설정(접근성)에 반응해 크기가 동적으로 조절되는 단위.
    - 용도: 오직 텍스트 크기(`fontSize`)를 지정할 때만 사용. (사용자가 시스템 폰트를 키우면 텍스트도 비례해서 커짐)


- 데이터의 흐름
    - 상태(State)는 상위 컴포넌트에서 하위 컴포넌트로 아래를 향해 흐름 (`Screen` ➔ `NewsFeed` ➔ `Story Widget`).
    - 대부분의 UI는 Stateless 이며 getter, setter 를 노출하지 않는다
    - **함수의 파라미터로 데이터를 받아 UI를 갱신한다**

- 이벤트의 흐름
    - 사용자의 클릭이나 상호작용 같은 입력 이벤트가 하위 컴포넌트(`Story Widget`)에서 발생함.
    - 발생한 이벤트가 상위 컴포넌트(`NewsFeed` ➔ `Screen`)를 향해 **위쪽 방향으로 전달**됨.
    - 상위 컴포넌트는 이벤트를 받아 상태(State)를 변경하고, 변경된 상태는 다시 데이터 흐름을 통해 아래로 내려가 UI를 갱신함.


- `TextStyle.copy()`의 동작 방식 (얕은 복사)
    - **새로 생성:** `TextStyle` 객체 자체는 새로 만들어짐 (`a != b`). 원본 색상을 바꿔도 영향 없음.
    - **참조 공유:** 내부 속성(`fontFamily` 등)은 새로 복사되지 않고 원본과 같은 객체를 가리킴 (`a.fontFamily == b.fontFamily`).

- 얕은 복사여도 안전한 이유
    - `TextStyle`, `FontFamily`, `Color`는 생성 후 값을 바꿀 수 없는 불변 객체(Immutable)임.
    - 내용을 변경할 수 없기 때문에 여러 곳에서 참조를 공유해도 부작용이 없어 깊은 복사가 불필요하고 메모리 효율적임.

- 얕은 복사가 문제가 되는 경우
    - 내부에 `MutableList`처럼 값을 바꿀 수 있는 가변 객체(Mutable)가 포함되어 있을 때만 주의 필요.
