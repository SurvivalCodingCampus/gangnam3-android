# 1. 배운 점

## Root - Screen 분리 패턴

> 화면을 **Root(외부 의존 처리)** 와 **Screen(순수 UI)** 두 단계로 나누는 패턴. Screen은 상태와 콜백만 받아서 그리기만 함.

### Root 패턴을 안 쓰면 생기는 문제

- **Screen이 ViewModel에 직접 의존**: Screen을 쓰려면 ViewModel이 반드시 있어야 함.
- **UI 테스트, Preview 작성이 어려움**: Preview에서는 ViewModel을 만들 수 없고, 테스트할 때도 ViewModel과 그 안의 Repository까지 같이 준비해야 함.
- **상태관리 라이브러리 교체가 어려움**: ViewModel 구조가 바뀌면 Screen 코드까지 같이 고쳐야 함.

### 역할 분리

| **구분**     | **Root**                                  | **Screen**                    |
| ---------- | ----------------------------------------- | ----------------------------- |
| **역할**     | 외부 의존 처리 (연결 담당)                          | 받은 상태로 화면만 그림                 |
| **하는 일**   | ViewModel 주입, 상태 구독, 화면 이동, 1회성 이벤트 처리    | UI 그리기, 사용자 입력을 콜백으로 전달       |
| **입력**     | ViewModel, 네비게이션 콜백                        | `UiState`, `onXxx` 콜백         |
| **테스트**    | 테스트 대상에서 제외                               | Preview, UI 테스트 대상            |

- **Root가 맡는 것**
  - ViewModel 주입, 상태 구독 (`collectAsStateWithLifecycle()`)
  - 화면 이동 (Navigation)
  - 1회성 이벤트 처리 (스낵바, 토스트, 화면 이동 이벤트)
  - Lifecycle, `remember` 등 초기화 처리
  - 권한 요청 등 외부 시스템 연결
  - 한마디로 **UI 테스트를 방해하는 모든 로직**을 Root로 옮김
- **Screen에서 하면 안 되는 것**
  - ViewModel 접근
  - Repository 직접 호출
  - 화면 이동
  - 비즈니스 로직

```kotlin
@Composable
fun SearchRoot(
    viewModel: SearchViewModel = viewModel(),
    onRecipeClick: (Int) -> Unit,
) {
    val uiState by viewModel.uiState.collectAsStateWithLifecycle()

    SearchScreen(
        uiState = uiState,
        onQueryChange = viewModel::onQueryChange,
        onRecipeClick = onRecipeClick, // 화면 이동은 Root 바깥에서 받아서 넘김
    )
}

@Composable
fun SearchScreen(
    uiState: SearchUiState,
    onQueryChange: (String) -> Unit,
    onRecipeClick: (Int) -> Unit,
    modifier: Modifier = Modifier,
) {
    // 상태와 콜백만 사용 → Preview, UI 테스트에서 가짜 값만 넣으면 바로 그려짐
}
```

- **장점**: Screen은 상태가 없는(stateless) 컴포저블이라 Preview에 `SearchUiState(...)`만 넣으면 됨. ViewModel이 바뀌어도 Root만 고치면 됨.

## Job과 onCleared

- **`viewModelScope`로 띄운 코루틴**은 ViewModel이 사라질 때 자동으로 취소됨.
- **직접 만든 Job/CoroutineScope**는 자동으로 안 끊김 → `onCleared()`에서 직접 `cancel()` 해줘야 함. 안 그러면 화면을 나가도 계속 돌아서 **메모리 누수**나 불필요한 작업이 생김.

```kotlin
class SearchViewModel : ViewModel() {
    private var searchJob: Job? = null

    fun onQueryChange(query: String) {
        searchJob?.cancel() // 이전 검색 요청 취소
        searchJob = viewModelScope.launch {
            // 검색 ...
        }
    }

    override fun onCleared() {
        super.onCleared()
        searchJob?.cancel() // ViewModel 종료 시 정리
    }
}
```
