# 1. 배운 점

## 기타

- **LazyRow / LazyColumn**: 화면에 보이는 항목만 컴포지션하고, 스크롤로 벗어난 항목은 그리지 않음 → 항목이 많아도 성능 유지. 항목이 바뀔 수 있으면 `key`를 지정해 주는 게 좋음.
- **targetSdk**: 앱이 어느 Android 버전의 동작 방식을 기준으로 할지 정하는 값. Google Play 정책상 일정 기간마다 최신 버전 근처로 올려야 업데이트 배포가 가능함.

## 국제화 (stringResource) 와 멀티플랫폼 고려

- 도메인/데이터 계층의 enum은 **Android의 `R.string`을 모르는 순수 Kotlin**으로 유지 → 멀티플랫폼(KMP)에서도 공유 가능.
- UI 계층에서 Mapper로 enum → 문자열 리소스로 변환. 테마 색상을 UI에서 입히는 것과 같은 느낌.
- `@StringRes`를 붙이면 반환값이 문자열 리소스 ID라는 걸 컴파일러/린트가 검사해 줌.

```kotlin
// domain - 순수 enum
enum class Category { KOREAN, WESTERN, JAPANESE }

// ui - Mapper
@StringRes
fun Category.toStringRes(): Int = when (this) {
    Category.KOREAN -> R.string.category_korean
    Category.WESTERN -> R.string.category_western
    Category.JAPANESE -> R.string.category_japanese
}

// 사용
Text(text = stringResource(category.toStringRes()))
```


## 화면 구성 방식의 변화

| **방식**                               | **특징**                              | **단점**                                       |
| ------------------------------------ | ----------------------------------- | -------------------------------------------- |
| **멀티 Activity**                      | 화면마다 Activity 하나                    | 화면 간 데이터 전달이 `Intent` + `Bundle`로만 가능해서 번거로움 |
| **싱글 Activity + Fragment**           | Activity 하나에 Fragment를 교체하며 화면 전환   | Fragment 생명주기가 복잡함                           |
| **싱글 Activity + Compose Navigation** | Activity 하나에 Composable을 교체하며 화면 전환 | -                                            |

## Navigation 3 핵심 개념

> Navigation 3는 **백스택을 개발자가 직접 리스트로 소유**하는 방식. 리스트에 키를 넣고 빼면 화면이 바뀜.

- **백스택 (Back Stack)**: 지나온 화면들이 쌓인 스택. 맨 위가 현재 화면.
  - 기존 Navigation 2에서는 백스택을 `NavController`가 내부에서 관리해서 `navigate()`, `popBackStack()` 정도로만 조작 가능했음.
  - Navigation 3에서는 백스택이 그냥 리스트라서 추가(`add`), 제거(`removeLastOrNull`), 교체(맨 위 항목 바꾸기) 등을 자유롭게 할 수 있음.
- **NavKey**: 화면 하나를 나타내는 키. 화면에 필요한 인자도 같이 담음.
- **NavDisplay**: 백스택을 보고 맨 위 키에 맞는 화면을 실제로 그려주는 최종 UI 컴포저블.
- **entryProvider**: 어떤 키가 어떤 화면(Composable)으로 그려질지 연결하는 곳.
- **entryDecorators**: 각 화면(entry)에 붙는 부가 기능. **ViewModel, 저장된 상태를 화면 단위로 얼마나 살려둘지** 결정함.
  - `rememberSaveableStateHolderNavEntryDecorator()`: 화면별 `rememberSaveable` 상태 유지
  - `rememberViewModelStoreNavEntryDecorator()`: 화면별 ViewModel 유지 → 백스택에서 빠질 때 ViewModel도 정리됨
  - **ViewModel decorator를 빼면**: ViewModel이 Activity에 붙음 → 화면을 나가도 안 사라지고, 같은 화면을 여러 번 열면(`Detail(1)`, `Detail(2)`) ViewModel 하나를 같이 써버리는 문제가 생김.
- Day 28의 **Root - Screen 패턴**과 연결됨: 화면 이동(`backStack.add`)은 Navigation에서 처리하고, Root는 콜백(`onItemClick`)만 받아서 넘김.

## 커스텀 Shape - 가운데가 파인 네비게이션 바

> `Shape` 인터페이스를 직접 구현하면 기본 제공(`RectangleShape`, `RoundedCornerShape`)으로는 안 되는 모양을 만들 수 있음.

### 요소 정리

| **요소**                            | **설명**                                                              |
| --------------------------------- | ------------------------------------------------------------------- |
| `Shape`                           | 컴포넌트의 외곽 모양을 정의하는 인터페이스. `createOutline()` 하나만 구현하면 됨               |
| `object`                          | 상태가 없는 모양이라 싱글톤으로 만들어 재사용 (매번 새로 생성 X)                              |
| `Size`                            | 모양이 그려질 영역의 가로/세로. **단위는 px**                                       |
| `LayoutDirection`                 | `Ltr` / `Rtl`. 아랍어처럼 오른쪽→왼쪽 언어 대응용. 이 모양은 좌우 대칭이라 안 씀               |
| `Density`                         | 화면 밀도(`density`)와 폰트 배율(`fontScale`)을 담고 dp/sp ↔ px 변환을 제공          |
| `density.density`                 | 1dp당 px 수. 예: xxhdpi 기기면 3.0 → `41f * d` = 123px                    |
| `Path`                            | 선을 이어 도형을 그리는 객체. **좌표 원점은 왼쪽 위 (0, 0)**, y는 **아래로 갈수록 커짐**         |
| `moveTo(x, y)`                    | 펜을 들어서 해당 위치로 이동 (선 안 그림)                                           |
| `lineTo(x, y)`                    | 현재 위치에서 해당 위치까지 직선                                                  |
| `cubicTo(x1, y1, x2, y2, x3, y3)` | 3차 베지어 곡선. (x1, y1), (x2, y2)는 곡선을 휘게 하는 **제어점**, (x3, y3)가 **도착점** |
| `close()`                         | 마지막 점과 시작점을 직선으로 이어서 도형을 닫음                                         |
| `Outline.Generic(path)`           | 임의의 Path로 된 외곽선. 그 외에 `Outline.Rectangle`, `Outline.Rounded`가 있음    |

### 포인트

- **px 단위로 계산해야 함**: `createOutline`은 px 기준이라, dp 값에 `density.density`를 곱해서 기기마다 같은 크기로 보이게 함.
  - `with(density) { 41.dp.toPx() }`로 써도 같은 결과. 이 방식이 더 읽기 쉬움.
- **`centerX` 기준 좌우 대칭**: 오른쪽 곡선은 왼쪽 곡선의 x 부호만 바꾸고 순서를 뒤집은 것 → 화면 폭이 달라도 홈은 항상 가운데에 위치.
- **곡선 숫자는 보통 디자인 툴에서 가져옴**: Figma에서 SVG로 내보낸 path 값을 옮긴 것. 직접 계산하는 값이 아님.
- **사용 방법**: `Modifier.clip(NavBarShape)`, `Modifier.background(color, NavBarShape)`, `Surface(shape = NavBarShape)` 등에 넘기면 됨. 홈 자리에 FAB 같은 가운데 버튼을 올리는 디자인에 많이 씀.
