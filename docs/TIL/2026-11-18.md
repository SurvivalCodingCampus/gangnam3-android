# 1. 배운 점

- **Toolchain**: 빌드에 사용할 JDK 버전을 프로젝트 단위로 고정하는 설정 (`kotlin { jvmToolchain(17) }`). 팀원마다 로컬 JDK가 달라도 동일한 버전으로 빌드됨.
- **컴포저블 분리**: 재사용 가능한 단위로 잘게 찢어 두는 게 좋음.
- **디자인 값은 한 곳에 정의**: 색상, 간격, 타이포 등을 Theme/상수로 정의해 두면 디자인 변경 시 **한 번에 갈아치우기** 가능.
- **dp 소수점 지양**: `0.5.dp` 같은 소수점 dp는 기기 밀도별 픽셀 변환 시 반올림 오차가 생겨 흐릿하거나 크기가 들쭉날쭉해질 수 있음. 정수 단위 사용.

## Modifier

> 컴포저블의 **크기, 배치, 모양, 동작(클릭·스크롤 등)** 을 꾸미거나 바꾸는 객체. 여러 Modifier를 `.`으로 **체이닝**해서 조합함.

- **불변 객체**: 체이닝할 때마다 기존 Modifier를 바꾸는 게 아니라 새 Modifier가 이어 붙여짐.
- **적용 순서가 중요**: 앞에서부터 차례로 적용되기 때문에 순서가 바뀌면 결과가 달라짐.

- **주요 Modifier 분류**:
  - **크기**: `size`, `width`, `height`, `fillMaxWidth`, `fillMaxSize`, `wrapContentSize`
  - **여백·위치**: `padding`, `offset`, `align`(Box/Row/Column 안), `weight`(Row/Column 안)
  - **꾸미기**: `background`, `border`, `clip`, `shadow`
  - **동작**: `clickable`, `selectable`, `toggleable`, `focusable`, `verticalScroll`
  - **접근성**: `semantics { }`, `clearAndSetSemantics { }`

### 컴포저블에 Modifier 파라미터 받는 규칙

```kotlin
@Composable
fun ProfileCard(
    name: String,
    modifier: Modifier = Modifier, // 첫 번째 선택 파라미터, 기본값 Modifier
) {
    Column(modifier = modifier.padding(16.dp)) { // 최상위 레이아웃에 적용
        Text(name)
    }
}
```

- **`modifier: Modifier = Modifier`**: 기본값을 줘서 호출하는 쪽이 생략 가능하게 함.
- **필수 파라미터 다음, 첫 번째 선택 파라미터로** 두는 게 관례.
- **최상위 레이아웃에 한 번만 적용**: 바깥에서 받은 `modifier`를 루트 요소에 넘겨야 호출부에서 크기·여백을 조절할 수 있음. 하위 요소에 재사용하면 의도치 않게 중복 적용됨.

## Modifier 활용

- **`Modifier.selectable()`**: 선택 가능한 항목(라디오 버튼 행 등)에 사용. `selected`, `role`을 지정하면 스크린 리더가 **"선택됨 / 선택 안 됨"** 같은 **접근성 힌트**를 읽어줌.
- **물결 효과(Ripple)**: `clickable`, `selectable` 등에 기본으로 적용되는 터치 피드백. 필요 없으면 `clickable(interactionSource = ..., indication = null) { }` 오버로드로 제거.
- **`Modifier.focusable()`**: 사용자 정의 컴포넌트가 키보드/D-pad **입력 포커스**를 받을 수 있게 함. (스크린 리더 포커스는 별개로, `semantics`로 제어)

## 선언형 다이얼로그

> 명령형(View)은 `dialog.show()`처럼 **직접 열고 닫는** 방식이지만, 선언형(Compose)은 **상태에 따라 그릴지 말지** 결정함.

```kotlin
var isOpen by rememberSaveable { mutableStateOf(false) }

if (isOpen) {
    AlertDialog(
        onDismissRequest = { isOpen = false },
        ...
    )
}
```

- **`isOpen` 상태로 표시 여부 제어**: 상태가 `true`면 다이얼로그가 그려지고, `false`면 사라짐.
- **`rememberSaveable` 사용**: 화면 회전 같은 구성 변경 후에도 다이얼로그가 열린 상태로 유지됨 (`remember`면 닫혀버림).

## API 버전 분기

- **`@RequiresApi()` 지양**: 런타임 보호가 아니라 Lint 경고용 표시일 뿐. 호출하는 쪽도 버전 체크를 하거나 같은 어노테이션을 붙여야 해서 계속 번져나가고, 결국 낮은 버전 기기 처리를 놓치기 쉬움.
- **`if`로 버전 분기**: 런타임에 버전을 확인해 대체 동작을 직접 작성.

```kotlin
if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S) {
    // Android 12 이상 전용 기능
} else {
    // 하위 버전 대체 처리
}
```

## WindowInsets (시스템 영역 처리)

> Edge-to-edge 화면에서 콘텐츠가 상태바, 내비게이션 바, 키보드 등 **시스템 UI에 가려지지 않도록** 여백을 주는 방법.

- **`Scaffold` → `innerPadding`**: `Scaffold`를 쓸 때는 넘겨주는 `innerPadding`을 콘텐츠에 적용 (상단바·하단바·시스템 바 영역 반영).
- **`Modifier.safeDrawingPadding()`**: `Scaffold` 없이 직접 처리할 때 사용. 상태바, 내비게이션 바, 카메라 컷아웃, 키보드 영역을 모두 피함.
- **키보드(IME)만 따로 처리할 때**: `Modifier.imePadding()` 또는 `Modifier.windowInsetsPadding(WindowInsets.ime)` 사용.

## Flow

> 시간에 따라 **여러 값을 순차적으로 방출**하는 코루틴 기반 비동기 데이터 스트림. 숫자처럼 계속 변경되는 값을 다룰 때 사용.

- **LiveData와의 차이**: LiveData는 Android 전용 API로 Lifecycle과 묶여 있어 순수 Kotlin 단위 테스트가 어려움. Flow는 순수 Kotlin이라 테스트 용이.
- **`flow { }` 빌더**: 블록 내부가 suspend 영역이라 `delay` 등 suspend 함수 호출 가능.
- **`emit()`**: Flow에서 값을 방출.
- **`launchIn(scope)`**: 지정한 코루틴 스코프에서 Flow 수집 시작 (해당 스코프의 디스패처에서 실행).
- **`flowOn(Dispatchers.IO)`**: 업스트림(Flow 생성·연산 부분)이 실행될 디스패처 지정.
- **`debounce()`**: 지정한 시간 동안 새 값이 안 들어오면 그때 마지막 값만 방출. 기본 연산자로 지원됨 (검색창 입력 등에 유용).

### Cold Stream vs Hot Stream

| **구분**        | **Cold Stream** (`Flow`) | **Hot Stream** (`StateFlow`, `SharedFlow`) |
| ------------- | ------------------------ | ------------------------------------------ |
| **데이터 생성 시점** | **수집(collect)하는 시점**에 생성 | 수집 여부와 상관없이 **바로 방출**                      |
| **구독자별 동작**   | 수집할 때마다 처음부터 새로 실행       | 여러 구독자가 같은 스트림 공유                          |
| **마지막 값**     | 남지 않음                    | 마지막 데이터가 남아 있음 (`StateFlow`)               |

### zip vs combine

| **구분**    | **zip**                                        | **combine**                                                  |
| --------- | ---------------------------------------------- | ------------------------------------------------------------ |
| **방출 조건** | **모든 Flow가 값을 방출**해야 짝지어 하나로 합침                | 모든 Flow가 한 번씩 방출한 뒤부터, 어느 하나라도 방출될 때마다 다른 Flow의 **최신 값**과 합침 |
| **용도**    | **순서대로 1:1 짝**이 필요할 때 (예: 두 API 결과를 한 쌍으로 합치기) | 여러 상태의 **최신 값 조합**이 필요할 때 (예: UI 상태 만들기)                     |

- **zip이 UI 상태에 안 맞는 이유**: 한쪽 Flow가 느리면 짝이 맞을 때까지 기다려서 화면 갱신이 늦어지고, 한쪽이 더 방출하지 않으면 계속 멈춰 있음. UI는 항상 최신 값을 보여줘야 하니 `combine`이 적합함.

### StateFlow vs SharedFlow

| **구분**   | **StateFlow**      | **SharedFlow**                |
| -------- | ------------------ | ----------------------------- |
| **초기값**  | 반드시 필요             | **가지지 않음**                    |
| **값 보관** | 항상 **최신 값 1개** 유지  | 기본적으로 보관 X (`replay`로 설정 가능)  |
| **용도**   | 화면 상태(UI State) 유지 | **원타임 이벤트** 처리 (토스트, 화면 이동 등) |

- **Flow → State 변환**: `stateIn()` / `shareIn()`으로 Cold Flow를 Hot Flow로 변환 가능. Compose에서는 `collectAsStateWithLifecycle()`로 `State`로 받아 사용.
